## Week 2 Goal

This week is about making your JavaScript foundation **strong enough to solve practical problems**, while starting to work like a software developer by using Git.

Week 1 taught you the basic building blocks. This week you will learn how to manipulate data more effectively, write more flexible functions, understand scope, use higher-order array methods, and keep your work safely versioned with Git.

By the end of the week, you should be able to take a small data-processing problem, decompose it into functions, transform collections of data, and maintain your work in a Git repository.

You will learn:

- Number methods and `Math`
- Useful string methods
- Ternary and nullish coalescing operators
- `switch`
- More useful array operations
- Loop control
- Rest parameters
- Anonymous and arrow functions
- Scope
- Higher-order functions
- `map`
- `filter`
- `reduce`
- `forEach`
- Git fundamentals
- GitHub repositories
- Commits
- Push and pull

### Not this week

Do **not** study:

- TypeScript
- Classes/OOP
- Node.js
- Express
- NestJS
- PostgreSQL
- HTTP APIs
- DOM
- React/Angular
- Advanced Git branching workflows
- GitHub Actions / CI/CD

Those come later. Right now, become better at **programming with JavaScript** and establish basic version-control habits.

# Rules for the Entire Week

### 1. You must type the code yourself

Do not copy the code from the video. Pause the video, close it, and reproduce the idea yourself.

### 2. No AI-generated solutions

You may ask AI to:

- generate test cases for your solution
- check whether your output matches a requirement
- explain an error message
- explain a concept you already attempted to use
- give you a hint without giving the solution

You may **not** ask:

- "Solve this exercise."
- "Write the code for me."
- "Fix my whole solution."
- "Give me the answer."

### 3. Try before asking

When stuck:

1. Read the problem again.
2. Write down what you know.
3. Try a solution.
4. Inspect the error/output.
5. Only then ask for a hint.

### 4. Do not memorize syntax without using it

Every new concept must immediately be used in an exercise.

### 5. Keep every day's work

Use the same folder from Week 1 and add a Week 2 folder:

```text
backend-career-shift/
├── week-01/
│   ├── day-01.js
│   ├── day-02.js
│   ├── day-03.js
│   └── day-04.js
└── week-02/
    ├── day-01.js
    ├── day-02.js
    ├── day-03.js
    └── day-04.js
```

Do not delete failed attempts. They are part of your learning record.

### 6. Commit your work

Starting this week, important completed work should be committed to Git.

Do not worry about writing perfect commit messages yet. The goal is to build the habit of saving meaningful progress.

# AI Verification Protocol

After completing an exercise yourself, AI may be used for verification.

Good prompts:

> Here is my JavaScript solution and the exercise requirements. Do not rewrite my code. Give me 5 test cases I can use to verify it.

> Here is my output. Compare it against these requirements and tell me only which requirements are not satisfied. Do not provide the solution.

> Explain this JavaScript error in beginner-friendly terms. Do not give me the corrected code.

> I attempted this problem for 20 minutes. Give me one conceptual hint only, without pseudocode or code.

For Git:

> I ran these Git commands and got this output. Explain what state my repository is in. Do not tell me the exact next command.

Bad prompts:

> Solve this for me.

> Write the function.

> Fix this code completely.

> Give me the correct answer.

> Give me the exact Git commands I should run without explaining what they do.
